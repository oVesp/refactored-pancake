# Animation pipeline

Animations are `Animation` instances. A manifest per set records each clip's uploaded asset id; one tool turns the manifests into the instances the game loads. Mechanics reference for `docs/game-design.md` §7.

## Pieces

| Piece | Role |
|---|---|
| `content/animations/<set>.json` | Manifest per set: `kind` (`enemy` for `AnimSet` rigs, `skill` for clips named by `SkillDef.animation`, `stock` for Roblox stock clips), and per clip its role, looping, markers, tier, notes, uploaded `assetId` (or an `alias` of another clip) and id history. Source of truth for everything below. |
| `src/ReplicatedStorage/Animations/<Key>.model.json` | One `Animation` per clip (`AnimationId`, `Looped` attribute, plus `Hit` seconds when the clip has that marker: the client falls back to it if the published asset lacks the marker). Generated by `sync`; never edit by hand. |
| `src/StarterPlayer/StarterPlayerScripts/Client/Animation/Animations.luau` | Client loader: `Animations.Get(key)` and `Animations.Load(animator, key, priority, looped)`. `GuardAnimations` and `WeaponAnimations` drive the guard and weapon-idle clips. |
| `src/ReplicatedStorage/Content/AnimRoles.luau` | Enemy role contract (`Idle`, `Walk`, `Attack`, `Death` required; `Run`, `Throw`, `Hit` optional) and the marker names. `EnemyAnimationController` loads every role a set has. |
| `tools/anim/anim.py` | `status` (clips without an id) and `sync` (writes the `Animation` files and the animation rows of `content/register.json`). |
| `tests/specs/Animations.spec.luau` | Fails the gate when a manifest, its `Animation` file, a marker name or a required role disagrees. |

## Markers

Every clip uses the same marker names (`AnimRoles.Markers`), set in the Animation Editor before publishing:

| Marker | Frame |
|---|---|
| `Hit` | A melee swing, throw or deflection takes effect (the swing VFX and sound wait for it). |
| `Release` | A projectile leaves the hand or bow. |
| `Step` | A footfall. |

The manifest's `markers` records the times of the markers inside the published clip (documentation; `sync` rejects other names). A clip published with other marker names must be re-published.

## Tiers

- **placeholder**: any clip not authored by the owner for this game. Action Forge (Quaternius, CC0), Roblox stock and agent-made clips are placeholders.
- **final**: an owner-authored clip. A clip becomes final only when the owner says so when handing it over.

## Workflow

1. Animate in Studio (Animation Editor), add the markers above, publish, and copy the animation id.
2. Put the id in the clip's `assetId` in the manifest (set `tier`; move a replaced id into `history`). A new clip is a new entry; a new set is a new `content/animations/<set>.json`.
3. `python tools/anim/anim.py sync`, then commit the manifest, the `Animations/*.model.json` files and `register.json` together.

A swap changes only the id, so gameplay code never notices. A new enemy role: add it to `AnimRoles.Enemy` with priority and looping, make the server cue it through `AnimCue`, then add the clip to each set; required roles fail the gate until every enemy set has one.
